### 2.2 外壳与导航

- 顶层使用 `overrideredirect(True)`（`ui.py:186-190`），自绘 42px 标题栏。
- 标题栏左段 224px 深色品牌区，右段浅色窗口控制区（`ui.py:302-340`）。
- 主骨架为固定 224px 深色侧栏 + 主区（`ui.py:578-650`）。
- 侧栏分“运行中心”（概览、日志）和“配置管理”（设置、连接），底部有客户端状态卡、切换版本、打开目录。
- 页头包含面包屑、页面标题、版本副标题、状态胶囊、计时及设置入口（`ui.py:656-690`）。
- 4 个页面启动时全部构建并以 `place` 叠放，切页仅 `lift()`（`ui.py:692-720`）。这是正确的性能优化，避免了旧版重排白屏。

### 2.3 信息架构判断

现有功能入口完整，但概览同时承担“操作台、指标仪表盘、流程状态、分布分析、质量分析、日志表”六种职责，首屏层级偏重。页头的面包屑、大标题、版本说明与卡片内标题又形成重复层级。Linear 式改造不应继续堆卡，而应以“连接是否就绪 → 试运行/正式运行 → 当前进度 → 异常与日志”为主任务链。

### 3.2 缺失或不完整的通用能力

- 无统一的对话框、Toast、Tooltip、Dropdown/Select、表单字段、验证提示、上下文菜单组件。
- 除 `Btn` 外，自绘交互控件普遍没有 `takefocus`、焦点环、Enter/Space 操作或角色语义。
- `Switch`、`Chip`、`Stepper` 没有一致禁用态；`IconBtn` 没有键盘操作。
- 图标混合 Segoe MDL2 私有码位、PNG 图片和 `✓/○/●/✕` 字符，风格、线宽和光学尺寸不受同一规范约束。

## 4. 主题、字体、颜色、间距与圆角

### 优点

- `theme.py` 集中定义颜色 `C`、字体函数 `f/icon`、4px 基础间距和圆角常量。
- 新版 UI 页面内未发现散落的 `#RRGGBB`，颜色令牌复用较好。
- 语义色、导航色和文本层级已有初步分类。

### 差距

- 当前是浅色内容区（`#F5F7FB`）+ 白卡 + 高饱和品牌蓝（`#2864F0`）+ 深海军蓝侧栏，不是全深色 Linear 工作台。
- 卡片圆角 16px、控件 10px、导航选中整块蓝底，使界面更偏传统管理后台；目标是更小圆角、弱填充、细分隔线和中性选中态。
- 页面仍有大量直接写入的像素尺寸与间距，如页头 94、卡片内边距 20、间距 10、控件高 34，令牌只覆盖一部分几何规则。
- `RADIUS_WINDOW`、`HEADER_H`、`C["overlay"]`、`C["log_text"]` 等未见有效消费；`label()`/`divider()` 的部分参数也未落实，令牌和 API 有“定义即完成”的假象。
- 字体使用磅值而布局使用 Tk 像素；在 DPI 缩放时两者增长模型不同。图标依赖 Windows 字体，缺少缺字回退验证。
- 没有独立背景层级、焦点色、选中色、禁用色、滚动条悬停色及 dark-only 对比度验收规则。

## 5. 动画系统及性能

### 已有基础

- `motion.py` 使用单一 16ms `root.after` 时钟，所有短动画共享，空闲停止。
- 支持 Windows 动画开关及 `TBE_REDUCED_MOTION=1` / `TBE_NO_ANIM=1`。
- 按钮、卡片、开关、导航、状态、进度和日志有统一时长；控件销毁时多数会取消动画。
- 页面已常驻，避免切页重建；日志淡入有 0.5 秒频率限制和 12 个并发上限。

### 问题与风险

1. `_show_page(..., animate=True)` 的参数没有使用，`motion.slide_in()` 也无调用，README 所述“页面切换轻位移”与当前实现不一致。
2. `Canvas._draw()` 普遍 `delete("all")` 后重建文本和多边形；圆角每角 18 段，悬停/按压每帧都付出重绘成本。Tk Canvas 无抗锯齿，加密弧线只能缓解，不能达到 Qt 矢量渲染质量。
3. `Panel.fit()` 同步调用 `update_idletasks()`，再安排两轮 idle；多处调用可能放大布局抖动和重入风险。
4. 每条日志在 `_drain()` 中同时 append 到 `LogTable` 和 `LogView`，即双份解析、标签和 Text 内容。`LogView` 超过 3000 行会裁剪，`LogTable` 没有同等上限。
5. `LogTable.set_search()` 遍历所有历史行并逐行查询 tag；随运行时间增长，搜索成本上升。
6. `StatCard.set()` 在指标变化时立即 `_draw()` 且可能另有脉冲动画；高频批次下存在重复绘制。
7. `_save_dt_token()` 在主线程执行网络校验，最长参数为 8 秒，会直接阻断事件循环；这比视觉动画更容易被用户感知为“卡顿”。

## 6. 缩放、DPI、自适应与无边框窗口

### 当前实现

- 初始尺寸根据 `SPI_GETWORKAREA` 计算，限制在 820–1280 × 620–880，支持 `TBE_UI_SIZE` 调试尺寸（`ui.py:174-189`）。
- 使用 `SetProcessDpiAwareness(1)`，即系统 DPI 感知，不是 Per-Monitor V2（`ui.py:2307-2313`）。
- 品牌 PNG 根据 `winfo_fpixels("1i")` 选择尺寸（`ui.py:198-210`）。
- 概览按宽度切换 compact：固定 4 列指标、缩短按钮、隐藏接管按钮/部分日志工具；按高度隐藏中段分析卡（`ui.py:735-808`）。
- 设置/连接使用滚动区，窗口边缘有 4px 自绘拖拽热区；最大化、最小化、任务栏入口和 DWM 圆角均直接调用 Win32。

### 主要限制

- 没有监听 DPI 改变，也没有按显示器获取工作区；跨屏移动和副屏最大化不可靠。
- 字体的磅值随 DPI 变化，而 42/94/224 等几何像素并未统一缩放，存在切字和拥挤风险。
- compact 只覆盖概览，设置中的长说明、单行运行参数和连接操作仍可能横向拥挤。
- `_apply_compact()` 会隐藏接管按钮，`_sync_mode_actions()` 又可改写按钮文案，状态与布局职责交叉。
- 顶边热区整段使用 `C["nav"]`，但标题栏右侧实际为 `C["bg"]`，实现注释也与分色标题栏矛盾。
- README 已明确记录：无边框窗口不一定获得 DWM 圆角，窗口仍可能为直角。这是路线评估的重要证据，不应靠继续增加多边形补丁掩盖。

## 7. UI 与业务逻辑调用关系

### 7.1 调用链

```text
app.py
  └─ tbeplus.ui.run_ui
      └─ App
          ├─ config.load_config / Config / APP_DIR
          ├─ client：端口检测、目标摘要、客户端定位/重启、配置写回
          ├─ dingtalk：客户端准备、token 监视/校验、目录和窗口操作
          ├─ newsapi：token 读取与缓存
          └─ engine：LikeEngine.ensure_http / run、parse_user_date、summarize
```

- 正式/试运行入口：`_on_run` / `_on_dry_run` → `_start` → 工作线程 asyncio loop → `_run_job`。
- `_run_job` 调用 `LikeEngine.ensure_http()`，应用 UI 配置，再调用 `LikeEngine.run(limit=...)`（`ui.py:2244-2286`）。
- 业务日志通过 `queue.Queue` 回主线程，这是正确的线程边界；`ui_queue` 负责状态和完成事件。
- 业务层没有导入 UI，依赖方向总体保持为 UI → business。

### 7.2 耦合点

1. `App` 同时管理窗口、页面、配置、任务状态、token、日志统计和 asyncio 生命周期，2324 行形成“上帝对象”。
2. `_run_job` 在工作线程直接读取 `StringVar` 和自绘控件值（`ui.py:2264-2281`）；Tk 变量不是可靠的后台线程接口。应在启动前于主线程形成不可变 `RunRequest`。
3. UI 用正则解析引擎文本（`板块：`、`列表里共 N 篇`、`[i/n] 状态 标题`）来驱动统计；引擎对应输出见 `engine.py:2270/2305/2363/2394`。文案或空格变化会 silently 破坏进度。
4. 状态词映射同时存在于 `ui.py`、`widgets.py` 和引擎文本，缺少单一事件/枚举定义。
5. `ui_classic.py` 复制了任务启动、接管、日期和配置应用流程，但不是当前入口，也无运行时切换开关；它会随业务演进成为过时副本。

## 8. 测试覆盖

- 唯一测试 `tests/test_websocket.py` 是手工运行的协议自检脚本，不是 UI 测试，也未接入标准测试发现。
- `_shot.py` 能固定页面截图，但没有图像基线、像素差异阈值、断言或 CI。
- 未覆盖：页面导航、版本切换、设置联动、运行/停止状态、事件统计、日志筛选/搜索/复制、token 校验、确认框、DPI、多屏、减少动态效果、窗口操作、exe 启动与 Tk/Qt 迁移回归。
- 因缺少 characterization tests，直接重写 UI 的最大风险不是“样式不像”，而是原本可用的任务流程被悄悄改变。

## 9. 结论

现有 UI 已具备可复用的令牌、自绘控件、动画时钟、队列回线程和页面缓存，不应简单推倒业务层。但它要达到高品质全深色 Linear 风格，需要继续对抗 Tk 的圆角抗锯齿、控件语义、动画、DPI、对话框和测试限制，并进一步堆高自绘代码复杂度。

**建议路线：PySide6 渐进式替换表现层，保留 `engine.py/client.py/newsapi.py/config.py` 等业务能力；先建立回归基线和主线程请求 DTO，再并行构建新外壳，最后按页面切换。** 如果“零第三方依赖”是不可谈判约束，则退而求其次保留 Tkinter，并把目标调整为“Linear -inspired”，不承诺同等视觉、可访问性和自动化测试水平。详见《Tkinter 与 PySide6 技术路线对比》。
