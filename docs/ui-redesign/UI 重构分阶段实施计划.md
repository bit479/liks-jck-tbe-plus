# UI 重构分阶段实施计划

## 1. 实施原则

1. 本计划从人工确认第一阶段文档后才开始；当前阶段只交付文档，不修改任何源码。
2. 先锁定行为，再改变视觉；先隔离业务，再迁移页面；最后才修改正式入口和打包。
3. 每个任务有独立验收和回退点。默认使用 fake engine、模拟日志和测试 token，不在自动化中执行真实点赞。
4. `engine.py/client.py/newsapi.py/config.py` 的业务规则不得因“顺便优化”而改变。
5. 每个阶段结束必须人工验收，不自动进入下一阶段。

## 2. 阶段总览与发布门

| 阶段 | 目标 | 发布门 |
| --- | --- | --- |
| P0 现状审查 | 7 份文档、路线建议、任务拆解 | 人工确认本文档与技术路线 |
| P1 回归基线 | 固定当前关键行为和视觉基线 | 基线可重复执行，真实写操作有隔离 |
| P2 技术验证与依赖决策 | 验证 PySide6 关键风险；或确认 Tk 降级 | 依赖/许可/外壳/DPI/打包获人工批准 |
| P3 表现层契约 | DTO、事件、日志模型、控制器，不改业务算法 | 旧 UI 用新契约跑 fake 流程且统计一致 |
| P4 设计基座 | 深色令牌、图标、核心组件、外壳 | 组件状态矩阵和键盘/DPI 验收通过 |
| P5 逐页迁移 | 版本页、连接、设置、日志、概览逐页平等 | 每页独立验收；旧路径仍可运行 |
| P6 整体硬化 | 动效、性能、异常、隐私、可访问性 | 全回归、性能和长时间模拟运行通过 |
| P7 打包与切换 | 实验 exe、干净机器、正式入口切换 | 人工批准发布；保留明确回退包 |

## 3. P1：回归基线（换栈前必须完成）

| ID | 小任务 | 主要产出/范围 | 独立验收 |
| --- | --- | --- | --- |
| B01 | 固定源码基线 | 记录 commit、Python/Tk/Windows/字体/截图环境 | 同一基线可重建；不混入未记录改动 |
| B02 | 日志分类单测 | 为 `LogView.classify`、`LogTable.parse` 收集现有中英文样例 | 每类状态的级别、分组、标题断言通过 |
| B03 | 运行文本解析单测 | 为 `_ingest` 的板块、总数、条目、小结建立独立样例 | 统计与旧版一致，重复 index 不重复计数 |
| B04 | 设置状态单测 | 日期快捷项、至今、板块、快速/复查、limit/restart | 生成的配置值和计划摘要与当前实现一致 |
| B05 | 运行状态表征 | fake coroutine 覆盖准备/运行/停止/成功/异常 | 按钮、状态、计时和错误优先级有断言 |
| B06 | 截图基线 | 用 `_shot.py` 固定 5 个界面状态、2 版本、2 尺寸 | 基线可重复，截图不含真实 token |
| B07 | 窗口人工基线 | 记录最小化、最大化、拖拽、四边缩放、副屏 | 有截图和检查记录，已知限制单列 |
| B08 | 协议测试回归 | 继续运行 `tests/test_websocket.py` | 现有 PASS 不因 UI 工作退化 |

**完成条件**：B02–B06 形成可重复测试入口；测试默认不访问内网、不写 config/state、不启动真实客户端。

## 4. P2：技术验证与依赖决策

| ID | 小任务 | 主要产出/范围 | 独立验收 |
| --- | --- | --- | --- |
| T01 | 人工确认硬约束 | 决定是否允许 PySide6 作为唯一新增 GUI 依赖 | 有书面路线选择；未批准则走 Tk 降级 |
| T02 | Qt 视觉最小样例 | 深色面板、按钮、输入、SVG、焦点、菜单 | 与设计规范状态矩阵一致，150% 无切字 |
| T03 | Qt 外壳最小样例 | 比较原生标题栏和 DWM 自绘外壳，只选一种 | 拖动、snap、最大化、最小化、跨屏通过 |
| T04 | Qt 日志最小样例 | Model/View、搜索、筛选、10 万模拟事件压力场景 |  UI 可持续交互，内存有界，筛选口径正确 |
| T05 | Qt 业务桥最小样例 | fake worker → signal → UI；RunRequest 快照 | 无 worker 读取控件，过期 run_id 被忽略 |
| T06 | Qt 实验打包 | 独立实验入口/spec，不替换正式构建 | 干净 Windows 可启动、资源和配置路径正确 |
| T07 | 许可与发布评审 | 记录依赖版本、许可、声明和分发方式 | 项目所有者明确接受，否则停止 Qt 路线 |
| T08 | Tk 降级验证（条件任务） | 仅 T01 不批准依赖时执行 | 明确可接受的视觉/键盘/测试边界并签字 |

**完成条件**：路线不是凭偏好决定，而是由 T02–T07 证据支持。技术验证代码与正式入口隔离。

## 5. P3：表现层契约与线程边界

| ID | 小任务 | 主要产出/范围 | 独立验收 |
| --- | --- | --- | --- |
| A01 | 定义 RunRequest | 主线程收集模式、范围、参数和配置快照 | worker 不读取 Tk/Qt 变量；快照不可变 |
| A02 | 集中日志事件适配 | 将现有文本解析集中为一个 LegacyEventAdapter | 同一录制日志生成事件与旧统计一致 |
| A03 | 建立 RunController | 管理 run_id、starting/running/stopping/finished | 快速重复点击、过期完成事件不会串状态 |
| A04 | 建立 ConnectionController | 旧版/钉钉准备、状态、token 校验 | 网络在后台；校验中可防重，失败可恢复 |
| A05 | 建立有界 LogModel | 单数据源、筛选、搜索、原始导出 | 双视图数据一致；清空/复制/导出语义明确 |
| A06 | 旧 UI 接契约验证 | 不改视觉，仅验证适配层可支撑当前功能 | fake 全流程和现有 UI 行为表征通过 |
| A07 | 直接引擎事件评估 | 只在适配器不足时提出增量事件接口 | 不改变引擎算法；有双口径对比后才替换 |

**回退点**：契约层出现问题时可撤回适配器接入，业务模块仍保持原接口。不要在此阶段修改页面样式。

| D07 | 对话框与浮层 | Dialog/Toast/Tooltip/Menu | 模态焦点圈定、Esc、安全默认按钮通过 |

**完成条件**：先通过组件陈列页/测试页验收，再进入业务页面；陈列页不进入正式用户导航。

## 7. P5：逐页迁移（每页均可独立验收）

推荐顺序先连接和设置，再日志，最后复杂概览；版本页可与外壳一起完成。

| ID | 小任务 | 验收重点 |
| --- | --- | --- |
| M01 | 版本选择与版本菜单 | 两版本互斥；运行中禁止切换；确认文案和回退正确 |
| M02 | 账号与连接：共享概览 | 版本/客户端/token/执行方式正确，凭证默认脱敏 |
| M03 | 账号与连接：钉钉流程 | 一键准备、后台监视、手动校验、成功/失败、重复点击 |
| M04 | 账号与连接：旧版流程 | 接管确认、端口状态、文件选择、目录入口 |
| M05 | 任务设置：处理范围 | 日期、至今、快捷范围、板块、错误提示 |
| M06 | 任务设置：运行方式与摘要 | 所有参数进入 RunRequest；运行中快照不被修改 |
| M07 | 任务设置：高级维护 | 重载配置、打开目录、版本信息和回退语义 |
| M08 | 运行日志 | 筛选/搜索/暂停/复制/导出/清空与旧版一致 |
| M09 | 概览：主操作与运行状态 | 准备/试运行/正式/停止，状态优先级和确认框 |
| M10 | 概览：指标与当前进度 | 录制事件对比旧版计数、进度、计时和当前条目 |
| M11 | 概览：实时日志和折叠详情 | 与完整日志一致，低高度保留主任务，质量无虚构数据 |
| M12 | 全局异常与空状态 | 无 token、无板块、无日志、搜索空、网络失败、导出失败 |

**每页共同验收**：正常/紧凑尺寸、100/150% DPI、键盘、减少动态效果、fake 成功/失败、截图对比、业务调用参数一致。每页完成后可独立回退该页，不能影响其他页。

## 8. P6：整体硬化

| ID | 小任务 | 独立验收 |
| --- | --- | --- |
| H01 | 动效统一 | 全部时长来自规范；减少动态效果立即到终态 |
| H02 | 高频性能 | 模拟连续事件、快速切页、连续搜索和尺寸拖动 |
| H03 | DPI/多屏 | 100–200%、跨屏、当前显示器最大化、窗口还原 |
| H04 | 键盘与焦点 | 全页面 Tab 走查、快捷键、弹窗、隐藏页焦点 |
| H05 | 隐私审查 | token、截图、日志导出、Toast 和错误文本不意外泄密 |
| H06 | 长任务生命周期 | 停止、关闭、重复任务、过期事件、后台 watcher 退出 |
| H07 | 视觉回归 | 5 界面 × 2 版本 × 关键状态 × 尺寸矩阵 |

H02 的通过标准应在技术验证后固化为可测指标，至少包括：事件循环持续响应、日志内存有上限、搜索不遍历失控、切页无重建白屏；禁止用模糊“感觉流畅”验收。

## 10. 依赖关系与提交粒度

```text
P0 人工确认
  → P1 基线
  → P2 路线决策
  → P3 契约
  → P4 基座
  → P5 逐页（M02–M04 → M05–M07 → M08 → M09–M11）
  → P6 硬化
  → P7 打包与切换
```

- 每个 ID 或一组同组件小 ID 对应一次可审查提交，不把全阶段压成一个提交。
- 文档、测试、业务适配、视觉、打包分别审查，便于定位回归。
- 每阶段结束更新实际差异和验收结果，但不擅自扩大需求。
