# 新版 UI 信息架构

## 1. 重构目标与边界

新版围绕一个核心问题组织：**“我现在能否安全地对哪个版本、哪些板块、哪个时间范围执行什么任务？”**

保留现有 5 个界面状态（版本选择 + 4 个页面）及全部业务能力，不因视觉改造增加新闻业务、账户系统或虚构的历史记录。主要变化是：减少重复标题与卡片、统一全局状态、将“连接准备”纳入主任务链、用结构化状态替代日志文本驱动页面。

## 2. 一级导航

```text
TBE+ 工作台
├─ 当前工作版本：老版本 TBe+ / 钉钉版 TBe+
│
├─ 运行中心
│  ├─ 任务概览       默认页；准备、试运行、正式运行、实时结果
│  └─ 运行日志       当前完整日志；筛选、搜索、复制、导出、清空
│
├─ 配置管理
│  ├─ 任务设置       时间范围、板块、运行参数、计划摘要
│  └─ 账号与连接     客户端/token 状态、准备引导、手动凭证
│
└─ 侧栏底部
   ├─ 精简连接状态   未连接 / 准备中 / 已就绪 / 异常
   └─ 打开程序目录
```

版本切换放在侧栏顶部版本菜单中；设置页保留同一入口作为上下文操作，但二者调用同一控制器。任务运行中禁止版本切换，并解释原因。

## 3. 全局外壳

### 3.1 标题栏

- 左侧：应用图标 + `TBE+ 工作台`，只出现一次。
- 中部可作为拖拽区，不放无意义面包屑。
- 右侧：最小化、最大化/还原、关闭。
- 优先采用能稳定支持 Windows 窗口管理的外壳；不能为了视觉一致性牺牲 snap、跨屏、任务栏和键盘行为。

### 3.2 页面工具栏

每页统一包含：

- 左侧：页面标题 + 一行当前上下文（例如“钉钉版 · 纯 HTTP”），不再同时堆叠面包屑、大标题和长副标题。
- 右侧：全局连接状态 + 当前页操作。
- 运行计时只在运行/完成后显示；账号和设置图标不重复占用工具栏。

### 3.3 全局状态优先级

```text
运行失败 / 连接异常
  > 正在停止
  > 正在运行 / 正在准备
  > 已完成 / 已停止
  > 已就绪
  > 未连接 / 空闲
```

状态优先级只是显示规则，不改变业务状态机。全局状态来自 `RunController + ConnectionController`，不能由多个页面各自覆盖。

## 4. 页面结构

### 4.1 版本选择 / 首次引导

**目的**：选择互斥的运行版本，并解释连接差异。

```text
应用标识
标题：选择工作版本
说明：板块和连接方式不同
├─ 老版本 TBe+：客户端会话、3 个板块
└─ 钉钉版 TBe+：token / 纯 HTTP、聚合资讯
```

- 使用两个简洁选项行或小面板，不使用大面积彩色插画卡。
- 选择后进入：老版本 → 概览；钉钉版无 token → 账号与连接；有有效缓存 → 概览。
- 后续从版本菜单切换时显示影响确认；不新增“自动判断版本”等未验证逻辑。

### 4.2 任务概览

按主任务流从上到下排列：

#### A. 就绪与主操作区

- 当前版本、连接/登录状态、选定板块和时间范围的短摘要。
- 主按钮：老版本为“开始点赞”，钉钉版为“开始任务”。
- 次按钮：“试运行”。
- 准备操作：未连接时显示为明确次按钮；已连接时降级为“重新准备”并放入更多菜单或低优先级位置，**不能因窄窗口直接消失**。
- 正式运行显示风险确认；试运行不显示写操作确认。

#### B. 当前运行区

- 状态：就绪 / 准备中 / 运行中 / 正在停止 / 已完成 / 已停止 / 失败。
- 总进度、当前板块、当前资讯、已用时。
- 运行时主按钮禁用，停止按钮可用；停止后状态明确为“正在停止”，不能立即伪装为已停止。
- 三阶段步骤保留为辅助反馈：连接 → 读取 → 执行。

#### C. 紧凑结果统计

固定 4 项：已处理 / 新点赞 / 原本已赞 / 未成功。

- 使用原口径，不用装饰性彩色卡片。
- 有总数时显示进度；快速模式下说明统计口径限制。
- “待复查”不能静默并入失败或成功；可在未成功/质量详情中单独展示，具体口径须与引擎现有汇总核对。

#### D. 实时日志

- 默认显示当前运行关键事件和逐条结果。
- 工具：搜索、全部/关键/问题、暂停滚动、查看全部。
- 高度不足时优先保留此区；分布和运行质量进入可折叠“运行详情”，不占首屏固定高度。

#### E. 运行详情（折叠，次级）

- 处理结果分布。
- 成功率、平均耗时、当前批次。
- 无数据时显示 `—`，不生成虚假百分比。

### 4.3 运行日志

```text
页面工具栏：运行日志 | 导出 / 复制 / 清空
筛选工具行：搜索 | 全部 / 关键 / 问题 | 暂停滚动
日志表：时间 / 级别 / 进度 / 状态 / 资讯标题
```

- 概览和完整日志读取同一日志模型，不再各存一份。
- “复制”复制当前筛选可见内容；“导出”导出当前运行完整原始日志；按钮 Tooltip 明确差异。
- “清空”只清空当前 UI 日志，不影响统计结果或业务历史；若产品希望同时重置统计，需另设操作，不能隐式绑定。
- 搜索命中高亮；无结果显示“没有匹配项”，与“尚无日志”区分。

### 4.4 任务设置

按用户决策顺序分为 4 组：

1. **处理范围**：日期从/到、至今、快捷范围、板块选择。
2. **运行方式**：快速模式、点赞后复查、每板块最多篇数、每 N 篇重启客户端。
3. **本次计划**：始终可见的摘要，使用用户语言列出版本、板块、日期、模式和上限。
4. **高级与维护**：版本/应用版本、连接参数摘要、重新读取配置、打开目录。

变化：

- 将“版本”从首张强调卡移至高级/全局版本入口，避免抢占处理范围。
- 控件标签位于控件上方或左侧稳定栅格中，说明位于下方，窄屏转单列。
- 设置修改立即更新摘要；实际引擎配置仍按现有语义在任务启动时生成快照。
- 运行中设置是否可编辑需明确：建议允许编辑“下次任务”，但当前运行继续使用旧快照，并显示“下次运行生效”。

### 4.5 账号与连接

#### 共享：连接概览

显示当前版本、客户端状态、token 状态、执行方式。默认只显示掩码摘要，不显示完整凭证。

#### 钉钉版

1. 一键准备（启动并接管）。
2. 引导用户打开新闻资讯。
3. 后台检测 token，显示等待/校验/成功/失败。
4. 手动 token 作为折叠的兜底区；默认掩码、支持显示/隐藏、校验中防重复提交。

#### 老版本

- 显示调试端口、客户端运行状态和视图数量。
- 准备并接管客户端有明确重启确认。
- 找不到程序时提供选择 TBe.exe 和打开目录。

钉钉版与老版本的专属区域互斥显示，沿用当前业务硬约束：钉钉版不启动或读取旧版客户端。

## 5. 状态与异常流

| 场景 | 页面表现 | 可执行操作 |
| --- | --- | --- |
| 首次启动 | 版本选择，无误导性运行按钮 | 选择版本 |
| 未连接 | 概览显示准备提示；可查看设置 | 准备、查看连接、试运行按现有可用性 |
| 准备中 | 状态为准备中，按钮防重复，日志持续更新 | 查看日志；安全停止按业务支持 |
| 已就绪 | 显示版本与执行方式 | 试运行、正式运行 |
| 运行中 | 进度/当前条目/计时更新，危险操作禁用 | 停止、查看日志 |
| 正在停止 | 停止按钮禁用，保留真实状态 | 等待当前文章结束 |
| 已完成 | 显示结果和用时，状态不清空 | 再运行、导出、查看失败项 |
| 已停止 | 保留已处理结果，明确未处理项 | 再运行 |
| 失败 | 显示可读原因，详细堆栈仅进日志 | 重试、检查连接、导出日志 |
| 空日志 | 一步引导到概览或开始任务 | 开始/返回概览 |
| 搜索无结果 | 保留日志，提示没有匹配 | 清除搜索 |

## 6. 表现层与业务层契约

### 6.1 启动请求（主线程生成）

```text
RunRequest
- mode: old | dingtalk
- dry_run: bool
- selected_boards: list[str]
- since / until: str
- limit: int
- restart_every: int
- read_state: bool
- verify: bool
- config_snapshot
```

worker 不再访问 Tk/Qt 控件。校验错误在启动前返回字段级提示；运行后的配置快照不可被界面编辑改变。

### 6.2 运行事件（worker 发出，UI 线程消费）

```text
RunStarted(run_id, request)
ConnectionChanged(state, detail)
SectionStarted(run_id, name)
SectionTotal(run_id, name, total)
ArticleFinished(run_id, name, index, total, status, title)
SectionFinished(run_id, name, stats)
RunFinished(run_id, result | error | stopped)
LogAppended(run_id, timestamp, level, raw_text)
```

- 第一版可通过适配器把现有日志解析集中到一处，避免大改引擎；后续再由引擎直接发结构事件。
- 每个事件带 `run_id`，过期事件不得覆盖新任务。
- 文案与统计解耦，日志仍保留原始文本用于导出和故障排查。

## 7. 旧版到新版映射

| 现有能力 | 新版位置 | 处理 |
| --- | --- | --- |
| 两张大版本卡 | 首次版本选择 + 侧栏版本菜单 | 保留能力，降低视觉重量 |
| 概览 4 指标 | 概览紧凑统计 | 保留口径 |
| 执行任务/步骤/当前资讯 | 概览主操作与当前运行区 | 合并层级 |
| 分布/质量 | 概览折叠运行详情 | 保留，不默认抢空间 |
| 双日志 | 单模型双视图 | 保留入口，消除重复数据 |
| 设置全部字段 | 任务设置 4 组 | 不删字段 |
| 钉钉/旧版连接 | 账号与连接互斥区域 | 保留业务约束 |
| 原生确认框 | 统一模态确认 | 保留安全确认 |
| 打开目录/重载配置 | 侧栏底部/高级维护 | 保留 |

## 8. 信息架构验收

1. 新用户从版本选择到完成试运行，不需要猜测连接步骤。
2. 任意页面都能看出当前版本、连接状态和是否有任务运行。
3. 正式点赞前能核对板块、日期和运行模式。
4. 900×700 与 150% DPI 下，必要操作仍可达，无因 compact 消失的唯一入口。
5. 空、运行、停止、失败和完成状态不会互相覆盖。
6. 现有功能均有新位置；未获批准不新增业务页面或删除能力。
