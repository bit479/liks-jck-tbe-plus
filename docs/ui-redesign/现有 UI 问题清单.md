# 现有 UI 问题清单

## 使用说明

- 优先级：**P1** = 重构前/重构中必须处理，影响正确性、安全或主要体验；**P2** = 明显影响 Linear 目标或长期维护；**P3** = 清理和一致性改进。
- 难度：S = 局部小改；M = 跨多个组件/页面；L = 需要架构或技术栈调整。
- 下列问题均来自基线 `29de5ed` 的实际源码或现有截图。“风险”指实施改进时的潜在回归，不代表问题只是推测。
- 本清单只记录和建议，不在本阶段修复。

## P1：正确性、隐私与回归保障

### UI-001　主线程同步校验 token，窗口可能无响应

- **涉及文件**：`tbeplus/ui.py:1549-1566`；`tbeplus/dingtalk.py:246-252`。
- **具体问题**：点击“保存并校验”后，在 UI 事件处理函数中直接调用 `dingtalk.token_valid()`；后者创建 `NewsApi` 并执行网络检查，默认超时 8 秒。
- **产生原因**：表现层事件函数直接承载同步 I/O；`update_idletasks()` 只能刷新一次，不能让后续网络调用保持响应。
- **改进建议**：主线程只收集输入并进入“校验中”状态；后台执行校验，结果通过队列/信号回主线程；期间禁用重复提交并允许安全取消。
- **实施难度**：M。
- **潜在风险**：重复回调、过期结果覆盖新输入、退出时线程仍回写 UI；需用请求 ID 和生命周期测试防回归。

### UI-002　后台任务线程直接读取 Tk 变量和控件

- **涉及文件**：`tbeplus/ui.py:2062-2102`、`2244-2281`。
- **具体问题**：`_run_job` 在工作线程的 asyncio loop 中读取 `StringVar.get()`、`Stepper.get()` 等；Tk 调用应归主线程管理。
- **产生原因**：业务协程直接捕获 UI 对象，没有在任务启动时建立数据边界。
- **改进建议**：在主线程生成冻结的 `RunRequest`（模式、日期、板块、limit、开关等），worker 仅接收 DTO 和 `Config` 副本；UI 状态通过明确事件返回。
- **实施难度**：M。
- **潜在风险**：字段漏拷、默认值变化、运行中修改设置的语义变化；必须用配置快照测试锁定行为。

### UI-003　运行统计依赖解析人类可读日志

- **涉及文件**：`tbeplus/ui.py:48-68`、`1979-2034`；`tbeplus/widgets.py:1224-1250`、`1470-1494`；`tbeplus/engine.py:2270`、`2305`、`2363`、`2394`。
- **具体问题**：页面用正则和中英文状态词从文本推断板块、总数、进度和结果；同一映射散落多处。
- **产生原因**：引擎只提供 `log(str)`，没有结构化运行事件；表格和统计都复用文本流。
- **改进建议**：新增不改变引擎算法的适配层事件，如 `RunStarted/SectionStarted/ArticleFinished/RunFinished`；保留原始文本仅用于展示和导出。
- **实施难度**：L。
- **潜在风险**：事件与旧日志口径不一致；先用录制日志做 characterization tests，再双跑对比旧/新统计。

### UI-004　没有 UI 回归测试，现有截图脚本不断言

- **涉及文件**：`tests/test_websocket.py`；`_shot.py:85-117`；整个 `tbeplus/ui.py` / `widgets.py`。
- **具体问题**：唯一测试覆盖 WebSocket/CDP；`_shot.py` 只保存 PNG，没有基线比较和结果断言。
- **产生原因**：自绘 Canvas 缺少可查询语义，测试设施未随 UI 重构建立。
- **改进建议**：先补纯逻辑单测、 fake engine 状态测试和截图基线；PySide6 路线再增加 Qt 控件/快捷键自动化。真实点赞不得成为默认测试。
- **实施难度**：M。
- **潜在风险**：基线截图环境敏感、测试误报；固定字体/DPI/窗口尺寸，并保留人工视觉复核。

### UI-005　token 在普通输入框中完整显示

- **涉及文件**：`tbeplus/ui.py:1369-1386`、`1430-1431`；现有截图 `docs/screenshots/04-账号与连接.png`。
- **具体问题**：缓存 token 被回填到普通 `Entry`，页面和截图可见完整凭证；概要的掩码处理没有应用到手动输入框。
- **产生原因**：把“编辑凭证”和“展示凭证状态”混为同一字段，缺少默认遮蔽及截图脱敏规则。
- **改进建议**：默认掩码显示，提供显式“显示/隐藏”和复制按钮；已缓存状态优先只显示掩码摘要；所有新截图使用伪 token。
- **实施难度**：S。
- **潜在风险**：用户编辑时误覆盖旧值；只有用户主动进入编辑状态才填入可编辑内容，并做保存确认。

## P2：体验、视觉目标与架构

### UI-006　整体视觉与全深色 Linear 目标相反

- **涉及文件**：`tbeplus/theme.py:12-78`；`tbeplus/ui.py` 各页面。
- **具体问题**：浅灰页面、白色大卡片、高饱和蓝色按钮/选中项，与目标深灰黑、低饱和强调色不符。
- **产生原因**：现有主题明确以“深色只出现在侧栏，内容浅底白卡”为设计原则。
- **改进建议**：按《Linear 风格设计规范》重建 dark semantic tokens，而不是对白底逐个反色；减少卡片边界，以分区、留白和细线建立层级。
- **实施难度**：M（Tk）/ M（PySide6）。
- **潜在风险**：简单反色导致对比度、原生 Entry/Text 和 PNG 图标异常；需全页面、全状态验收。

### UI-007　概览信息过载且卡片层级过多

- **涉及文件**：`tbeplus/ui.py:824-1016`；截图 `01-概览-钉钉版.png`。
- **具体问题**：指标、执行、步骤、板块、当前条目、分布、质量和日志同屏竞争；大标题、页头副标题和卡片标题重复。
- **产生原因**：以“仪表盘模块堆叠”而非任务流组织首屏。
- **改进建议**：首屏只保留连接/运行主操作、紧凑关键指标、当前进度和日志；分布与质量降为按需展开的次级区域。
- **实施难度**：M。
- **潜在风险**：用户找不到旧指标；保留相同数据口径，通过折叠区或二级标签承载，不删除功能。

### UI-008　compact 状态与操作文案/可见性相互交叉

- **涉及文件**：`tbeplus/ui.py:539-551`、`751-808`。
- **具体问题**：compact 会隐藏接管按钮并缩短文案；`_sync_mode_actions` 又直接设置长文案，且 `_apply_compact` 在布尔值不变时提前返回，模式切换后可能留下不一致状态。
- **产生原因**：窗口尺寸、版本模式和运行状态分别修改同一批控件，没有统一状态派生。
- **改进建议**：用单一 `ViewState → ViewModel` 计算按钮文本、可见性和禁用态；任何状态变化都走同一 render/update 路径。
- **实施难度**：M。
- **潜在风险**：改变现有“窄窗口隐藏准备按钮”的行为；应由产品确认是否改为溢出菜单，而非直接恢复所有按钮。

### UI-009　设置页和连接页缺少真正的窄宽重排

- **涉及文件**：`tbeplus/ui.py:1117-1388`、`1568-1571`。
- **具体问题**：长标题说明、日期行、运行参数和 token 操作都使用横向 `pack`；所谓自适应只调整卡片左右 pad，没有分行/换列策略。
- **产生原因**：compact 只实现于概览，其他页依赖滚动区解决高度而不解决宽度。
- **改进建议**：建立表单栅格，低于断点时标签和控件纵向排列；长说明使用动态 wraplength；主操作保持可见。
- **实施难度**：M。
- **潜在风险**：Tk 动态换行会触发高度重算；需覆盖 900px 最小宽度和高 DPI。

### UI-010　双日志视图重复写入，概览日志缺少统一容量控制

- **涉及文件**：`tbeplus/ui.py:1665-1700`；`tbeplus/widgets.py:1253-1277`、`1496-1530`。
- **具体问题**：每条消息分别 append 到 `LogTable` 和 `LogView`；前者没有后者的 3000 行裁剪，搜索又遍历全部行。
- **产生原因**：两个视图各自持有 Text 数据，没有共享日志模型和虚拟化。
- **改进建议**：建立单一有界日志 store，视图只保存投影；按批次刷新搜索/筛选，限制保留行数并明确导出语义。
- **实施难度**：M。
- **潜在风险**：清空、复制“当前筛选”与导出“全部日志”的口径可能改变；分别写测试。

### UI-011　自绘 Canvas 重绘成本高且无法消除锯齿

- **涉及文件**：`tbeplus/widgets.py:55-103` 及各 `_draw()`；`README.md:37-47`。
- **具体问题**：按钮/卡片每帧删除并重建全部图元；圆角多边形每角 18 段仍无真正抗锯齿。
- **产生原因**：Tk Canvas 绘图模型和 Windows 原生渲染能力限制。
- **改进建议**：Tk 降级路线应缓存静态层、只更新变化 item、限制并发；高保真路线使用 Qt 的抗锯齿矢量绘制，不再继续增加弧线分段。
- **实施难度**：M（优化）/ L（换栈）。
- **潜在风险**：局部重绘出现残影或状态不同步；以视觉基线和动画帧耗时验收。

### UI-012　页面切换动画接口闲置，文档与实现不一致

- **涉及文件**：`tbeplus/ui.py:708-720`；`tbeplus/motion.py:207-217`；`README.md:26-29`。
- **具体问题**：`animate` 参数未使用，`slide_in()` 无调用；当前切页只 `lift()` 和导航变色。
- **产生原因**：为解决重排白屏而缓存页面后，位移动效没有重新接入。
- **改进建议**：新版只给内容容器做 4–6px、120ms 内位移/淡入，不改变业务时序；减少动态效果时立即到终态；更新文档使其与实现一致。
- **实施难度**：S/M。
- **潜在风险**：叠放页面出现透明背景、残影或焦点落到隐藏页；需测试焦点和快速连续切页。

### UI-013　原生弹窗与自绘界面语言断裂

- **涉及文件**：`tbeplus/ui.py` 中 `messagebox`、`filedialog` 调用；`widgets.py` 无 Dialog。
- **具体问题**：确认、警告和文件选择使用系统默认样式，与应用深色、圆角、按钮和焦点规范不一致。
- **产生原因**：未建立统一 overlay/dialog 组件。
- **改进建议**：高风险确认采用统一模态对话框，支持明确后果、默认安全按钮、Esc 和焦点圈定；文件选择可继续使用系统对话框。
- **实施难度**：M（PySide6）/ L（Tk 自绘可访问模态）。
- **潜在风险**：自绘模态无法正确阻断后台或焦点逃逸；优先使用框架模态能力。

### UI-014　多数自绘控件缺少键盘和可访问性

- **涉及文件**：`tbeplus/widgets.py` 的 `Chip/Switch/Stepper/NavItem/IconBtn/ModeCard`；仅 `Btn` 在 `240-245` 支持焦点与键盘。
- **具体问题**：不能一致地 Tab 聚焦、查看焦点、Enter/Space 激活或方向键调整；也没有读屏角色和状态。
- **产生原因**：Canvas 只实现鼠标事件，缺少控件语义层。
- **改进建议**：定义焦点顺序和键盘矩阵；PySide6 优先使用标准控件/accessibleName；Tk 路线至少补焦点、快捷键和可见焦点环。
- **实施难度**：M（PySide6）/ L（Tk 完整语义）。
- **潜在风险**：快捷键与输入框冲突；按控件类型做自动化和人工键盘走查。

### UI-015　图标来源与绘制语言不统一

- **涉及文件**：`tbeplus/theme.py:81-100`；`widgets.py` 的 MDL2 码位和状态符号；`app_icon.py`/PNG 资产。
- **具体问题**：MDL2 图标、品牌 PNG、`✓/○/●/✕` 字符混用，尺寸、笔画和视觉重量不同。
- **产生原因**：按功能逐点补图标，没有统一图标网格和资产策略。
- **改进建议**：统一 16px 网格、1.5px 笔画、圆角端点；Qt 使用受控 SVG 图标集，Tk 降级方案预渲染多 DPI PNG；品牌插画与功能图标分开管理。
- **实施难度**：M。
- **潜在风险**：新增资产授权、缺失字体和打包路径问题；建立资产清单及回退图标。

### UI-016　DPI 方案不完整，多屏和动态缩放风险高

- **涉及文件**：`tbeplus/ui.py:174-210`、`233-300`、`2307-2313`。
- **具体问题**：使用系统 DPI 感知而非 Per-Monitor V2；字体磅值随缩放而像素几何不同步；工作区和最大化以单一 `SPI_GETWORKAREA`/`0,0` 处理。
- **产生原因**：Win32/Tk 混合窗口方案只针对启动时主屏做了修正。
- **改进建议**：Qt 使用框架高 DPI 与逻辑像素，并测试跨屏；若保留 Tk，统一 scaling、监听 DPI 变化、用 `MonitorFromWindow/GetMonitorInfo`。
- **实施难度**：M（Qt 验证）/ L（Tk 补齐）。
- **潜在风险**：修复缩放后所有断点和截图变化；按 DPI 矩阵逐项验收。

### UI-017　无边框热区与分色标题栏存在冲突，系统圆角不可靠

- **涉及文件**：`tbeplus/ui.py:266-300`、`393-462`。
- **具体问题**：顶部 `n/ne` 热区固定深色，但标题栏右侧是浅色；边缘颜色需要手工跟随页面。DWM 圆角调用允许静默失败。
- **产生原因**：自绘窗口边框没有单一布局源，外壳状态变化后需逐块同步热区颜色。
- **改进建议**：PySide6 优先采用 Windows 原生标题栏或经过验证的 DWM 自定义边框；若继续自绘，从同一布局模型派生热区，并做四边像素采样。
- **实施难度**：M。
- **潜在风险**：原生边框会改变品牌区和可用内容高度；两种外壳只能择一，不做多套补丁叠加。

### UI-018　全局鼠标滚轮绑定容易相互覆盖

- **涉及文件**：`tbeplus/widgets.py:1110-1152`。
- **具体问题**：`ScrollArea` 在进入时 `bind_all("<MouseWheel>")`、离开时 `unbind_all`，会影响其他滚动区域；页面又是常驻叠放。
- **产生原因**：用应用级绑定模拟滚轮焦点，缺少统一滚动路由。
- **改进建议**：按指针所在可见滚动容器路由事件，或使用框架原生滚轮传播；切页时显式释放旧页面状态。
- **实施难度**：S/M。
- **潜在风险**：日志与设置滚动优先级改变；覆盖嵌套/相邻滚动区及快速切页测试。

### UI-019　`App` 上帝对象混合所有职责

- **涉及文件**：`tbeplus/ui.py:135-2324`。
- **具体问题**：同一类包含 Win32 外壳、页面构建、导航、日志解析、表单、线程、asyncio、配置和业务调用。
- **产生原因**：多次迭代均向现有 `App` 追加方法，缺少页面/控制器边界。
- **改进建议**：拆为 Shell、各 Page/ViewModel、RunController、ConnectionController、LogModel；业务模块保持独立，页面不得直接读取后台 Tk 状态。
- **实施难度**：L。
- **潜在风险**：大拆分会同时改变行为；先提取纯状态和适配器，逐页迁移，每步可验收回退。

### UI-020　主题和组件 API 存在无效定义及不一致封装

- **涉及文件**：`tbeplus/theme.py:19`、`73-77`、`111-118`；`tbeplus/widgets.py:1709-1728`；`tbeplus/ui.py:113-132`、`1892-1893`。
- **具体问题**：存在未消费令牌、无效/忽略参数、空方法；`RadioChips` 在页面文件而非组件库。
- **产生原因**：增量修改后缺少令牌审计和组件 API 约束。
- **改进建议**：定义最小语义令牌表和控件 props/state 契约；删除动作留到获批准的实现阶段，先以静态检查/测试找出全部引用。
- **实施难度**：S。
- **潜在风险**：误删外部或动态调用；本阶段不删，实施前用搜索和测试确认。

## P3：遗留分支与交付一致性

### UI-021　`ui_classic.py` 是另一套无人入口调用的业务/UI 副本

- **涉及文件**：`tbeplus/ui_classic.py`；`app.py:65-67`。
- **具体问题**：旧 UI 复制接管、日期、任务运行等逻辑，但当前入口只导入新 UI，也没有环境变量或参数切换。
- **产生原因**：为回退保留整份旧实现，而非只保留可验证的版本标签或适配边界。
- **改进建议**：迁移期以 Git 标签和构建产物作为回退；若确需运行时回退，必须提供明确开关、共享 RunController 和双路径测试。
- **实施难度**：S（决策）/ M（真正可维护的回退）。
- **潜在风险**：直接删除会破坏未记录的下游导入；本阶段不动，先确认外部使用。

### UI-022　打包脚本含机器相关路径，迁移 Qt 时成本容易被低估

- **涉及文件**：`TBeAutoLike-1.8.3-win64.spec:5-13`、`38`；`build_exe.py:43-87`。
- **具体问题**：spec 使用旧的绝对路径；当前构建依赖 PyInstaller 单文件、资源路径和 `--selftest`。PySide6 还会引入 Qt 插件、DLL 和许可分发工作。
- **产生原因**：打包围绕 Tk 零依赖单文件优化，未为第二套 GUI 运行时准备验证。
- **改进建议**：新 UI 未达功能平等前不改正式打包；后续用独立实验 spec、相对路径和 Qt 插件清单，比较 one-folder/one-file 启动与体积，再人工批准切换。
- **实施难度**：M。
