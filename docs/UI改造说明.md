### 3. 数据流

```
用户点「开始点赞」
   └─ ui.App._on_run() → _apply_settings()（把界面选择写回 cfg）
      └─ LikeEngine(cfg, log=self.log).run()
         ├─ 日志经 queue 回主线程（ui._drain，80ms 轮询）
         ├─ ui._ingest() 解析日志里的 [i/total] / 板块名 → 驱动进度条与指标卡
         └─ 结束后 summarize() 输出汇总
```

**关键约束**：引擎只往 `log` 回调里写进度，没有结构化事件。所以界面不改引擎、
通过解析日志行来还原进度——这条链路本次保留，只把"解析结果怎么展示"重做了。

### 4. 改造前存在的问题

1. **一屏塞不下**：一个 840×620 的窗口里堆了状态、操作、参数、时间段、日志五个 `LabelFrame`，
   视觉上没有主次，用户不知道先点哪儿。
2. **样式不可控**：`ttk` 在 Windows 上走原生主题，颜色/圆角/悬停都改不动，
   和"专业工具"的观感差距大。
3. **信息不落地**：引擎跑起来只往日志里刷文字，界面上没有任何进度、计数、状态变化，
   用户只能盯着滚动的日志。
4. **启动假死**：`_refresh_status()` 在主线程扫 30 个端口，没开客户端时窗口白屏 30 秒。
5. **缺少反馈闭环**：没有空状态、没有运行中/已完成的状态标识，出错只有一行红字。

## 二、改造后的主要变化

### 1. 版面：从"表单堆叠"到"工作台"

```
┌────────────┬──────────────────────────────────────────────┐
│  深色导航   │  页面标题 / 说明            用时 · 状态 · 刷新 │ ← 白色标题栏
│  224px     ├──────────────────────────────────────────────┤
│  概览       │  ┌────┬────┬────┬────┐  指标卡（白卡）        │
│  运行日志   │  ├────┴────┴────┴────┤                        │
│  任务设置   │  │ 执行：三个按钮 + 进度 + 当前文章 │          │
│            │  ├──────────────────┤                        │
│  客户端状态 │  │ 板块进度（每板块一行）│                      │
│  打开目录   │  ├──────────────────┤                        │
│            │  │ 实时日志（自适应高度）│                      │
└────────────┴──────────────────────────────────────────────┘
```

- 深色只出现在左侧导航（`#172536`），内容区一律 `#F3F5F8` 浅底 + 白色卡片，
  长时间盯着不累眼，也符合"工业软件"的克制感。
- 导航按业务分成 **运行**（概览、运行日志）和 **配置**（任务设置）两组，
  当前项有深色底 + 左侧蓝色强调条。
- 顶部标题栏与导航联动，切换页面时标题、说明同步变化。

### 2. 交互：把"看不见的过程"变成"看得见的进度"

| 原来 | 现在 |
| --- | --- |
| 启动后白屏 30 秒 | 状态区先显示「检测中…」，端口探测放到**后台线程**，窗口立刻可用 |
| 只有日志在滚 | 4 个指标卡（已处理 / 新点赞 / 原本已赞 / 未成功）+ 总体进度条 + 每个板块的独立进度 |
| 不知道在跑哪篇 | 「执行」卡片实时显示当前文章标题 |
| 结束后没有结论 | 右上状态胶囊：空闲 / 运行中 / 正在停止 / 已完成 / 已停止，并记录用时 |
| 日志一片黑 | 按级别上色（板块=蓝、小结=绿、降速重试=橙、失败=红），支持「全部 / 关键 / 问题」三档过滤 |
| 空日志一片空白 | 空状态文案："还没有日志。点「准备并接管客户端」…" |
| 失败只有日志 | 「未成功」卡片变红并提示"可重跑补齐" |

### 3. 性能与稳定性（顺手修掉的真问题）

- **跨线程调 Tk**：原代码在 worker 线程里直接 `root.after(0, ...)`，
  偶发 `RuntimeError: main thread is not in main loop`。改为 `ui_queue` + 主线程轮询。
- **重复扫端口**：用户点「试运行」时若后台检测还没回来，会再扫 30 秒。
  改为等待后台结果（`threading.Event`），只扫一次。
- **卡片高度写死**：改文案就会切字。新增 `Panel.fit()` 按内容自适应
  （`after_idle` 补算两轮，解决 pack 高度延迟上报）。

### 4. 响应式

| 宽度 | 表现 |
| --- | --- |
| ≥ 1120 | 指标卡 4 列并排；设置页表单宽度上限 880，不拉满整行 |
| < 1120 | 指标卡 2×2；按钮文案收短（"准备并接管客户端" → "准备接管"）；板块胶囊 2 个一行 |
| 高度不足 | 设置页自动出现细滚动条（内容装得下时自动隐藏），不压字号、不切内容 |

所有尺寸随屏幕计算：`min(1280, max(800, 屏宽-48))`，窗口不会比屏幕还大。

## 七、已知问题 / 说明

1. **未与真实客户端联调**：本次环境里没有 TBe+ 客户端与新闻站 token，
   "准备接管 → 试运行 → 正式点赞"只验证到"无客户端时的提示与状态复位"。
   点赞主流程走的是原有未改动的 `engine.py`，风险仅限于界面层。
2. **原生对话框**：接管/点赞/关闭的二次确认仍用 `tkinter.messagebox`，
   与系统风格一致但无法套用深色或自定义样式。如需统一视觉，需要自绘弹窗（约 150 行），
   本次未做，避免过度设计。
3. **日志区中文为等宽字体的回退字形**：Consolas 不含汉字，Windows 会自动回退到宋体，
   在缩放比例非 100% 的屏幕上可能略显不齐。若要完全统一，可改为 `Microsoft YaHei UI`
   等宽替代（会牺牲对齐感），当前保留 Consolas 以保证数字/英文对齐。
4. **`ui_classic.py` 是死代码**：仅作回退备份，`app.py` 不再引用。确认新版稳定后可删除。
5. **未做深色模式**：任务书要求浅色工业商务风，未额外提供深色切换，避免维护两套配色。

## 九、1.6.0：两个版本入口 + 沉浸式标题栏（2026-10-27）

### 入口拆成两个版本

原来两个版本混在一个概览页里跑（板块列表里同时出现「新闻资讯」和「钉钉版e+新闻资讯」），
板块和配置互相牵连。现在**打开软件先选版本**：

| 版本 | 板块 | 引擎侧配置 |
| --- | --- | --- |
| 老版本 TBe+ | 新闻资讯 / 开讲了 / 进出口公司新闻资讯 | `portal_cards=[新闻资讯,开讲了]`、`skip_session_by_default=False`、`dingtalk_news=False` |
| 钉钉版 TBe+ | 钉钉版e+新闻资讯 | `portal_cards=[]`、`skip_session_by_default=True`、`dingtalk_news=True` |

- 选择页是两张可点的大卡片，进入后在「任务设置 → 版本」里可以随时切换；
- 每个版本只显示自己的板块（进度、勾选框、汇总都跟着变），**不会串味**；

## 十、1.7.0：统一动效与版本入口图标（2026-10-27）

### 技术边界（为什么这么做）

tkinter 的普通子控件没有 opacity/transform，也没有原生组件过渡，整窗 `-alpha`
一闪一闪只会让任务工具看起来不可靠。所以本版：

- **不引入任何动画库**，新增 `tbeplus/motion.py`（约 200 行，标准库）；
- 全部动画共用**一个** `root.after` 时钟（16ms），空闲即停，没有长期定时器；
- 页面切换用 **6~10px 缓动位移**替代假淡入，自绘控件（按钮/开关/导航/胶囊/进度条）
  做**颜色过渡**，日志做**前景色淡入**——这些都是真正的渐进变化，不是遮罩障眼法。

### 统一参数（`motion.py`）

| 动效 | 时长 | 说明 |
| --- | ---: | --- |
| 悬停 | 150ms | 按钮 / 导航 / 胶囊 / 指标卡边框 |
| 按压 | 100ms | 约 2% 内缩 + 混入深色 |
| 卡片 | 190ms | 入口卡 / 统计卡 |
| 页面切换 | 220ms | 8px 纵向位移，easeOut |
| 状态变化 | 190ms | 开关滑块、状态胶囊换色 |
| 进度条 | 280ms | 平滑推进到真实目标 |
| 日志淡入 | 150ms | 单行前景色 |
| 首屏交错 | 40ms | 统计卡依次出现 |

缓动统一 `cubic-bezier(0.22, 1, 0.36, 1)`（二分法求值），不做弹簧回弹和循环光带。

### 减少动态效果

优先级：`TBE_REDUCED_MOTION=1` / `TBE_NO_ANIM=1` → Windows「动画效果」系统开关 → 默认开。
关闭时所有动画**同步落到最终状态**：进度条直接到位、数值直接更新，任务不受任何延迟。

### 各处落点

- **页面**：`_show_page` 改为 place 管理 + `motion.slide_in`，切页只动新页面，不闪白；
- **首屏**：每个版本第一次进入概览时统计卡交错淡入（`StatCard.reveal`，同画布网点遮罩），
  之后切回不再重播；
- **按钮**：悬停变色 150ms、按下 100ms 内缩，禁用立即呈现、无误导反馈；
- **统计卡**：数值变化时数字短暂带语义色再回归，0.35s 节流，高频刷新不反复触发；
- **进度条**：`set()` 立即更新真实目标，显示值 280ms 平滑跟进；归零（新一轮任务）即时；
- **日志**：每行淡入 150ms；0.5 秒内超过 8 行自动降级停止淡入，并发淡入上限 12，
  不因动画改变消息顺序、级别与历史；自动滚动逻辑不变，手动上翻不会被拉回；
- **版本入口卡**：悬停边框/底色 190ms 过渡，两卡淡入 40ms 交错。

### 版本入口图标

- `旧版tbe+图标.png` → `assets/mode_old.png`（48×48）
- `ding-tbea.png` → `assets/mode_dingtalk.png`（48×48）
- 程序图标（窗口/任务栏/exe）仍是「眨眼宝宝点赞图标」。

### 改动文件

`tbeplus/motion.py`（新增）、`tbeplus/widgets.py`、`tbeplus/ui.py`、`tbeplus/__init__.py`（1.7.0）、
`assets/mode_old.png`、`assets/mode_dingtalk.png`、`README.md`、`docs/screenshots/*`。
业务文件 `engine.py` / `client.py` / `newsapi.py` / `config.py` 未改。

## 十二、1.8.0：钉钉版引导、token 自动接管与仪表盘（2026-10-28）

### 1. 钉钉版引导（新增「账号与连接」页）

按设计稿把钉钉版的使用路径做成一条明确的三步引导：

1. **一键准备**：自动查找并启动 `TBeHome.exe`（只认新版，见下）；
2. **打开「e+ → 新闻资讯」**：首次没有登录态时，程序把客户端窗口带到前台并轮询；
3. **自动接管 token**：从 TBeHome 进程内存读取 `tbea_art_token`，校验有效后写入
   `state.json`，随后点赞走纯 HTTP，客户端可关闭。

页面同时显示：当前版本、客户端是否启动、token 摘要、执行方式（纯 HTTP / 客户端会话），
并提供「打开新闻资讯」「打开客户端目录」「手动填写 token（32 位十六进制 + 在线校验）」。
首次进入钉钉版且没有 token 时，会自动触发「一键准备」；已有 token 时直接进任务概览。

### 2. 与旧版 TBe+ 的硬隔离

- `tbeplus/dingtalk.py` 只接受文件名 `TBeHome.exe`，找不到就明确报错，**没有旧版回退分支**；
- 钉钉模式的「准备」只走 `TBeHome`，不会调用 `resolve_client_exe` / `restart_client`；
- `LikeEngine.ensure_http()` 在钉钉模式没有 token 时抛 `DingtalkTokenRequired`，
  不再降级到客户端 CDP 会话；UI 的「开始任务 / 试运行」也会先跳回引导页；
- token 内存扫描在钉钉模式只扫 `TBeHome.exe`，不扫 `TBe.exe`；
- 老版本模式的板块、连接卡和接管逻辑保持原样。

### 3. 任务概览仪表盘

按 `TBePlus 自动化任务概览仪表盘.png` 和 `新建 DOC 文档.doc` 重排：

| 设计要求 | 实现 |

| 面包屑 + 标题 + 状态 | 顶部「运行中心 / 任务概览」、标题/副标题、状态胶囊、用时、设置入口 |
| 四张指标卡 | 已处理（数字/总数 + 2px 进度）、新点赞、原本已赞、未成功；统一 86px 高 |
| 执行控制台 | 状态点、`4 / 200 篇`、百分比、总进度条、三步流程、当前资讯与时间；主/次/危险按钮分层 |
| 处理进度 | 四段堆叠条 + 已点赞/原本已赞/待处理/失败图例（真实计数） |
| 运行质量 | 成功率、平均耗时、当前批次；无数据时显示「—」，不编造 |

| 底部信息 | 版本、当前模式、用途说明，弱化显示 |

窄窗口策略：指标卡保持四列；窗口高度不足 620px 时自动收起「处理进度/运行质量」，
把高度留给实时日志（900×700 实测日志区仍有 123px，可正常滚动）。

### 4. 关于“自动点开新闻资讯”的边界

新版 TBeHome 是钉钉 CEF 壳，实测**不接受** `--remote-debugging-port`，也没有可用的
命令行深链；因此无法可靠模拟点击「e+ → 新闻资讯」。本版做到：

- 自动启动、自动复用已登录客户端、自动把窗口带到前台；
- 每秒轮询 TBeHome 内存，用户点开新闻列表后**无需再点任何按钮**，自动接管并提示成功；
- 已缓存 token 时完全跳过客户端，直接纯 HTTP 运行。
